# ملاحظات التقسيم (اقرأها قبل أي تعديل مستقبلي)

## ✅ تم التحقق فعليًا
تم تشغيل هذا الموقع المُقسّم بالكامل (عبر محاكي متصفح حقيقي، وليس تخمينًا) وتأكدنا أنه:
- يحمّل كل ملفاته الـ 20 بدون أي خطأ JavaScript.
- يبني صفحة الهبوط بنجاح (نفس الناتج تمامًا كالملف الأصلي).
- كل عنصر برمجي (143 دالة/متغير/معالج حدث) من الملف الأصلي موجود في مكان واحد فقط في النسخة الجديدة — لا نقص ولا تكرار (تم التحقق برمجيًا عبر محلل JS حقيقي، وليس بحثًا نصيًا).

## ⚠️ الترتيب في index.html حرج — لا تغيّره
```
utils.js → state.js → supabase.js → router.js → (كل ملفات الميزات بأي ترتيب) → app.js (آخر ملف دائمًا)
```
السبب: `state.js` يستدعي `lsGet()` (من utils.js) فور تحميله. و`app.js` يستدعي `boot()` فور تحميله، وboot يحتاج كل شيء آخر جاهزًا. لو غيّرت الترتيب، الموقع سيتعطل بالكامل من أول تحميل.

## الانحرافات عن الهيكلة المطلوبة (وسببها)
- **أُضيف `js/core/utils.js`**: الهيكلة الأصلية طلبت فقط `app.js`، لكن فصل الأدوات العامة (esc, uid, toast...) عن معالجات الأحداث + boot() كان ضروريًا تقنيًا (شرح أعلاه) — وإلا الموقع ما راح يشتغل.
- **أُضيفت مجلدات `js/landing/`, `js/onboarding/`, `js/analytics/`**: هذه صفحات/ميزات فعلية بالموقع (صفحة الهبوط، معالج التهيئة بـ8 خطوات، صفحة التحليلات) لم تكن موجودة في الهيكلة المقترحة أصلاً، فأضفتها كمجلدات منفصلة بدل حشرها بمكان لا يناسبها.
- **ملفات `css/*.css` الفرعية شبه فارغة**: الموقع مبني على Tailwind utility classes بالكامل تقريبًا — لا يوجد CSS منفصل لكل صفحة في الكود الأصلي أصلاً. كل ملف فيه تعليق يوضح ذلك بدل تصميم مُختلَق.
- **`js/channels/channels.js` شبه فارغ**: لا توجد "قنوات" فعلية غير الويدجت نفسه في الكود الحالي؛ باقي القنوات مجرد أزرار "قريبًا".

## مجلد supabase/ (إضافي، ليس في الهيكلة الأصلية)
استخرجت أكواد الخادم (Edge Functions + SQL) من كتل `<script type="text/plain">` إلى ملفات حقيقية منفصلة لسهولة النشر:
- `supabase/functions/{ai-respond,verify-widget,kb-process,kb-crawl,kb-ingest}/index.ts`
- `supabase/sql/*.sql`
- `supabase/secrets.md`

**تنبيه:** أبقيت كتل `<script type="text/plain" id="src-...">` الأصلية داخل `index.html` أيضًا (لم أحذفها) — لأن صفحة "الإعداد/Setup" بالموقع تعرضها للمستخدم للنسخ مباشرة من المتصفح (ميزة "engSource"). لو حذفتها، هذه الميزة تتعطل. يعني نفس الكود موجود بمكانين الآن (بقصد): داخل index.html للعرض بالمتصفح، وفي supabase/ كملفات حقيقية للنشر السريع.

## كيف تستخدم هذا مع Qwen الآن
بما إن كل ملف أصبح صغيرًا (بين 5 و300 سطر تقريبًا بدل 1965 سطر)، مشكلة القطع عند 741 سطر يجب ألا تتكرر — Qwen 3.7 Plus يقدر الآن يعيد كتابة أي ملف من هذه كاملًا في رسالة واحدة. أرسل له ملف واحد محدد فقط في كل مرة (مثلاً js/knowledge/knowledge.js) مع طلب تعديل محدد، بدل الملف الكامل القديم.
